## Conclusion

The native pasted-content feature changes the saved user message. Both CCB's
polling anchor check and Stop-hook request extraction reject that envelope.
Actual Claude PTY turns and real remote answers demonstrate the bug; no fake
provider executable, manually wrapped input or mocked API was used in the
accepted final matrix. The wrapper was generated by the native client.

Controlled feature-cache configuration is test-only, not a claim that this
machine's normal default or every 2.1.283 installation enables the feature.

## Native cause and experimental controls

Read-only inspection of the pinned binary found the native serializer and
`tengu_virtual_pancake` gate. It adds leading newlines, matching opening and
closing ID attributes, and escapes embedded pasted-content tags. Its internal
ID validator currently uses four lowercase hex digits. These are versioned
implementation observations, not an upstream documented format contract.

The initial native launch reported its own automatic update; all accepted
comparisons explicitly pinned 2.1.283 and disabled its updater.
Initial ordinary user-settings runs returned model-unavailable errors; those
were not accepted as successful completion tests. Isolated settings using the
existing API environment produced real successful answers.

A probe variant with `DISABLE_TELEMETRY=1` did not produce wrappers even with
the test-local cache value true. Removing that test variable produced wrappers
in the final controlled runs. Thus a cached flag value alone is insufficient
as a reproduction guarantee. This observation does not justify changing user
telemetry settings as a product workaround.

Early harness issues were corrected: extra underscores in synthetic job IDs
violated the existing request-ID grammar, and immediate event inspection could
race the second concurrent hook. Final jobs use normal job_<alphanumeric> IDs
and both hook receipts are checked after commands finish. Early nonqualifying
artifacts remain in the test root, distinct from `final-*` accepted cases.

## Candidate repair

`lib/provider_core/claude_prompt.py` supplies a dependency-light shared helper.
The polling checker and hook transcript extractor call it before their existing
anchored checks. It strips exactly one full envelope with matching opaque,
case-sensitive IDs, allows outer whitespace, rejects nested/sibling wrappers,
malformed tags and outside text. It preserves ordinary unwrapped input.

The ID grammar excludes double quotes, angle brackets and whitespace but does
not assume four hex digits; this covers harmless future UUID-like IDs without
relaxing structural attribution. The helper does not change parent-chain
traversal, tool-result/subagent exclusion, queue activation or timeout policy.
An opening-tag match, closing-suffix check and one body scan avoid a large
backtracking whole-envelope regex. A local 20-iteration measurement took about
0.003 / 0.023 / 0.246 ms for valid 10k / 100k / 1M-character bodies. This is a
local observation, not a timing assertion in CI.
