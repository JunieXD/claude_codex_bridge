# v8.7.6

Released: 2026-10-06

## English

### Claude and Codex delivery reliability

- Recognize native Claude pasted-content envelopes when binding request anchors, reading lifecycle events and matching stop-hook completion. This repairs missed request recognition investigated in #354 while retaining top-level envelope and anchor checks.
- Recognize an empty Codex composer when its configurable status bar uses an undimmed separator or displays `Context 100% left`. Native placeholder styling, cursor and layout establish empty input without depending on model names.
- Preserve draft protection, busy/menu blocking, FIFO and the existing send-once behavior. Unknown nonempty custom layouts remain blocked; no blind Enter retry or duplicate paste is added.

### Verification and upgrade

- The fixes have native Claude envelope/hook/log evidence and guarded Codex 0.156.1 / 0.159.2 tests, including long pastes, draft/menu transitions and a real remote model response. Controlled local-API tests are distinguished from real model tests in the committed evidence.
- Update CCB and reopen the affected project when outstanding work can safely be interrupted so the updated daemon and provider startup hooks are loaded. No manual project, conversation or configuration migration is required.
- Release and mobile package metadata are synchronized; there is no new mobile interface behavior.

### Known limitations

- The empty-composer status-bar fix addresses a pre-send wait. The already-pasted-but-unsubmitted symptom in #356 has not been reproduced or conclusively attributed to this cause; the issue remains open.
- PR #366 and its experimental SSH remote-workspace feature are not included. Its separate file-synchronization fix remains on an isolated branch pending review and qualification.
- Native tests do not establish complete WSL2/Rocky or arbitrary custom-layout compatibility.

## 中文

### Claude 与 Codex 投递稳定性

- 在请求锚点绑定、生命周期事件读取和 stop-hook 完成匹配中识别 Claude 原生 pasted-content 包装，修复 #354 调查中发现的请求识别遗漏，同时保留顶层包装及锚点校验。
- Codex 自定义状态栏使用非暗色分隔符，或显示 `Context 100% left` 时，现在能够识别空输入框。通过原生占位符样式、光标位置和布局确认空输入，不依赖模型名称。
- 保留草稿保护、忙碌/菜单阻塞、FIFO 和单次发送行为。未知布局的非空草稿仍保守阻塞，不增加盲目回车或重复粘贴。

### 验证与升级

- 修复已具备真实 Claude 包装/hook/日志证据，以及 Codex 0.156.1 / 0.159.2 开启保护后的交互验证，覆盖长文本、草稿/菜单切换和真实远端模型回复。提交的证据记录明确区分本地可控接口测试与真实模型测试。
- 更新 CCB 后，请在待处理工作可以安全中断时重新打开受影响项目，使新版 daemon 和 provider 启动 hooks 生效。无需手动迁移项目、对话或配置。
- 发布及手机端包元数据同步更新；本版本没有新增手机界面行为。

### 已知限制

- 状态栏修复解决的是发送前等待。#356 描述的文字已粘贴但未提交现象尚未复现，也未确定与此同因，issue 继续保持开放。
- 不包含 PR #366 及其实验性 SSH 远程工作区功能。其文件同步修复保留在独立分支，等待审查和验证。
- 原生测试不代表完整 WSL2/Rocky 环境或任意自定义布局均已兼容。
